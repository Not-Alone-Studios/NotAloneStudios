# Common Delays in Bank Valuation Work and How Valuation Offices Can Reduce Them

A valuation delay rarely begins on the day the branch follows up.

By the time the branch calls to ask where the report is, the file has usually been stuck for a while — at a point no one was watching. The call is not the start of the delay. It is the moment the delay becomes visible outside the office, usually with pressure attached.

And here is the trap that catches most offices in that moment: the branch says the report is late, and "late" feels like the problem. So the file gets pushed — picked up, hurried, put at the top of the pile. But "late" is a symptom, not a diagnosis. The report could be late because a borrower is unreachable, because photos are still sitting on a site engineer's phone, or because a draft has been waiting on the valuer's desk for three days. Each of those needs a completely different response. Pushing the file harder does nothing if you are pushing it at the wrong point.

This article is about the step most offices skip: not how to track files, and not what to capture at intake — but how to *diagnose* a delay once you sense one, so you act on the real blockage instead of the symptom.

## The symptom is not the diagnosis

When something is late, the useful question is not "how do we speed this up." It is "where, exactly, is this file standing right now, and who is holding the next move."

Think of how a doctor works. "I have a fever" is not a diagnosis — it is the thing that sent the patient in. The actual work is finding what is causing it. A valuation office that hears "report is late" and immediately starts chasing the valuer, when the file is actually stuck on a document the borrower never sent, is treating the fever and ignoring the infection.

Most delays in bank valuation work hide one level below what the office first notices. The skill is learning to walk backward from the symptom to the stage where the file actually stopped.

## How to diagnose where the delay actually is

Here is a practical way to read the ten symptoms that show up most often. When a file feels stuck, match what you are *seeing* to what is *likely happening underneath*, decide whose move it really is, and note the one thing worth recording so the same file does not stall the same way twice.

| Delay seen by office | Likely root cause | Who should act next | What to record |
|---|---|---|---|
| Borrower not answering calls | Only one number captured; wrong digit or switched off; no alternate | Office staff — try alternate, then ask branch for an updated number | Each call attempt with date; the alternate contact once found |
| Site visit keeps slipping | Key holder is not the borrower (brother, watchman, tenant) and their availability was never fixed | Site engineer — coordinate directly with whoever actually has access | Who holds the key and which days/times they are reachable |
| Engineer reached the area but not the property | Landmark missing; the address alone is not enough for that locality | Office staff — get a landmark before re-dispatching | A clear landmark and a confirmed approach route |
| Visit done days ago, file hasn't moved | Photos still on the engineer's phone, never handed to the file | Site engineer — transfer images against the file reference | Visit date and photos tied to the assignment |
| Two files both stuck at the photo stage | Images from a two- or three-property route got mixed between files | Site engineer — separate and tag images by property | Which photos belong to which reference |
| Waiting on documents "since last week" | Borrower promised but never sent; no one was specifically chasing | Assigned staff — follow up; escalate to branch if borrower stays silent | What was promised, by when, and each follow-up |
| File complete but not reaching draft | Valuation inputs still with the valuer, who is out on site visits | Valuer — provide rates/area/judgment; office flags it on return | Which inputs are pending and when they were flagged |
| Draft looks done but isn't submitted | Typed draft waiting for the valuer to check and sign | Valuer — review and sign | Draft-ready date and review status |
| Report went back and forth, still not final | A correction was given verbally, never written, so the revision was never confirmed | Whoever raised the correction — confirm in writing once fixed | The exact correction and confirmation it is done |
| Old file resurfaces with a query, nothing can be found | Final PDF was sent, but photos and working file were never stored | Office — retrieve or reconstruct; store at submission from now on | Final report and evidence saved against the reference |

You will notice the "who should act next" column rarely points at the person the branch is pressuring. The branch pushes the office; the office pushes the valuer; meanwhile the file may actually be waiting on the person who has the keys. Diagnosis is what stops that misfire.

## Separate borrower-side, branch-side, and office-side delays

Once you can see where a file is stuck, the next question is whose side the delay sits on — because that decides what you can actually do about it. Most delays fall into three groups, and each calls for a different response.

**Borrower-side delays.** The borrower is unreachable, documents are not provided, or property access is controlled by someone who is never around. You can chase these. You can call, follow up, and ask the branch to nudge. What you cannot do is finish them alone. The discipline here is not speed; it is *evidence*. Keep a simple record of every attempt, so that when the branch asks, you can show the file has been moving and the hold-up is on the borrower's end — not the office's.

**Branch-side delays.** The original assignment came with incomplete details, instructions changed midway, or a query the branch itself needs to clarify is sitting unanswered. This is not about blaming the branch. It is about communicating clearly and keeping a record of the dependency. An unrecorded branch-side delay has a way of quietly turning into "the valuer was slow." A short note — *raised this point with the branch on this date, awaiting reply* — protects the office and keeps the real timeline honest.

**Office-side delays.** The file no one logged, the photos left on a phone, the draft waiting to be reviewed, the report that was sent but never filed. These sit entirely within the office's control, which means there is no one to wait for and no one else to blame. They should be cleared without ceremony. The uncomfortable truth is that the most fixable delays are usually the office's own — and they are the easiest to ignore precisely because no outside person is calling about them yet.

The value of splitting delays this way is simple: it changes what you *do* the moment you spot one. Borrower-side, you chase and record. Branch-side, you communicate and record. Office-side, you just fix it — today.

## Why this gets harder as volume grows

At low volume, an experienced office carries most of this in its head. The team remembers that the Hubballi file is waiting on the borrower's brother, and that two drafts are sitting with the valuer who has been out on visits all week. Memory works — until it doesn't.

The strain shows up when assignments arrive faster than anyone can hold them. A new assignment lands on WhatsApp during a site visit and is read but not acted on. A site engineer running three properties on one route comes back with a phone full of photos and no time to sort them. Office staff type reports while the valuer is out, drafts stack up for review, and a query on an old file arrives just as the final PDF for a new one is going out. None of these is a failure of effort. They are the exact points where files slip through the gaps — and diagnosis is how you find the slip before the branch does.

## FAQs

**How do I find where a bank valuation file is actually stuck?**
Work backward from the symptom. "The report is late" is what you notice; the real delay is usually one stage below it — an unreachable borrower, photos not handed over, inputs sitting with the valuer, or a draft awaiting review. Match the symptom to its likely cause before you decide who to chase.

**The branch says the report is late — what should I check first?**
Treat "late" as a symptom, not the problem. Trace the file to the exact stage it stopped at, then work out whose move it really is. Often it is not the person the branch is pressuring — the office gets pushed, but the file may be waiting on a document or a key holder.

**What is the difference between borrower-side and office-side delays?**
Control. Borrower-side delays — unreachable contact, documents not provided — can be chased but not finished by the office alone, so the priority is keeping a record of attempts. Office-side delays — unlogged files, photos on a phone, unreviewed drafts — are fully within the office's control and should be cleared at once.

**Why do reports stall even when they look finished?**
Two usual reasons: the draft is waiting on the valuer to check and sign, or a correction was given verbally and never confirmed against the revised version. Both look complete from the outside. Recording the correction and confirming it in writing keeps these files from looping quietly.

**How do I stop delays from hiding until the branch calls?**
Make a habit of noting, for each active file, where it stands and who owes the next move. It does not need to be elaborate — even a shared sheet listing the stage and the responsible person turns an invisible delay into one the office can see and act on before anyone outside notices.
