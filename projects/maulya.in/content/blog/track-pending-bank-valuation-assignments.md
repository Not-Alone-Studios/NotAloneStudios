# How to Track Pending Bank Valuation Assignments Without Losing Control

The most dangerous word in a valuation office is *pending*.

It sounds like information. It feels like a status. But it tells you almost nothing.

Pending on what? Waiting for whom? Stuck since when? Two files can both say "pending" while sitting in completely different places — one waiting for the borrower to answer a call, the other waiting on your own desk for a signature. Same word. Very different problems.

This article is about replacing that one vague word with something the office can actually act on.

## A list tells you what exists. A workflow tells you what is stuck.

Most offices have a list. An Excel sheet, a register, a WhatsApp group where the branch drops assignments. The list answers one question: *what work do we have?*

That is useful. But it is not the question that causes stress at month-end. The questions that actually hurt are:

- Which files are waiting for a site visit?
- Which are waiting for the borrower to pick up the phone?
- Which are waiting for photos or documents?
- Which are waiting for valuation inputs from the valuer?
- Which drafts are typed but not reviewed?
- Which reports are submitted but not saved anywhere you can find later?

A list does not answer these. A workflow does. The difference between the two is the difference between knowing you have forty files and knowing which six of them need action *today*.

## Why "pending" hides the real problem

When everything stuck is labelled "pending," the office loses the ability to see *where* work is stuck. And the stage where a file is stuck decides who should act next.

A file waiting for a site visit needs the site engineer.
A file waiting for documents needs a follow-up with the borrower or branch.
A file waiting for review needs the valuer.
A file waiting to be filed needs office staff.

If all four are called "pending," nobody knows whose move it is. So the file waits. Not because anyone refused to act, but because the status never told anyone to.

## The common pending stages in a valuation office

Most bank valuation work moves through a recognisable set of stages. The names will differ from office to office, and that is fine — what matters is that each file sits at exactly one of them at any time:

- **Received but not assigned** — the assignment has come in but no one owns it yet
- **Borrower contact pending** — assigned, but the borrower has not been reached
- **Site visit pending** — contact made, visit not yet done
- **Site visit rescheduled** — the visit slipped (keys unavailable, borrower travelling, address confusion)
- **Photos / evidence pending** — visit done but images not yet collected or organised
- **Documents pending** — waiting on a deed, plan, tax receipt, or similar, depending on the office's normal process
- **Valuation inputs pending** — the file is with the valuer for rates, area, and judgment
- **Report draft pending** — inputs given, draft not yet typed
- **Valuer review pending** — draft typed, waiting for the valuer to check and sign
- **Submission pending** — report ready, not yet sent to the bank
- **Storage / retrieval pending** — submitted, but the file and photos are not saved where they can be found again

You do not need all of these. A small office might use six. The point is not the exact list — it is that "pending" gets replaced by a *specific* stage.

## Every assignment needs four things

Strip everything else away, and a file under control has four answers attached to it:

1. **One current status** — where it is right now
2. **One responsible person** — whose move it is
3. **One next action** — what specifically needs to happen next
4. **One due date or expected timeline** — by when

When a file has all four, follow-up becomes calm. Anyone can look at it and know what to do.

When even one is missing, the file drifts. A file with a status but no owner waits for everyone. A file with an owner but no next action waits for clarity. A file with no due date waits forever — quietly — until the branch calls.

## A simple tracking table you can build today

You do not need software to start. You need columns that force the four answers.

A workable shared tracker might have these columns:

| Ref | Borrower | Bank / Branch | Current stage | Owner | Next action | Expected by | Notes |
|-----|----------|---------------|---------------|-------|-------------|-------------|-------|

One row might read:

> *VR-204 · R. Kumar · bank branch · Site visit rescheduled · Site engineer · Re-confirm keys with borrower, revisit Thursday · 12 June · brother has keys, works weekdays*

That single line tells the whole office where the file is, whose move it is, what must happen, and by when. No phone call needed to find out.

The discipline that makes this work is simple but strict: **one file, one current stage.** The moment a file is allowed to be "kind of at site visit, kind of waiting for documents," the tracker stops being trustworthy — and an untrustworthy tracker is worse than none, because people stop believing it.

## What to review daily

A tracker is only as good as the habit of looking at it. Ten minutes in the morning is usually enough for most offices:

- Files due today or overdue
- Files stuck at the same stage for too long
- Files with no owner
- Files waiting on the office's *own* action

That last point matters more than it looks. Some delays are on the borrower's side — an unanswered phone, a document not provided. You can chase them, but you cannot finish them alone. Other delays are entirely yours: a draft typed three days ago and still unreviewed, a submitted report never filed. The daily review should surface the second kind ruthlessly, because those are the files the office can clear without waiting for anyone.

## Why this quietly reduces follow-up stress

When the office can see the status of every file, the branch's follow-up call stops being a surprise. You already know where the file is before you pick up the phone. You can answer with a real next step and a real date, instead of "let me check and call you back" — which usually means the file had drifted.

This is also where the cost of running purely on memory and chat shows up. When the status lives only in someone's head or buried in a thread, the office cannot answer quickly, and follow-up becomes the de facto tracking system. ## A practical pending-tracking checklist

- [ ] Replace "pending" with a specific stage for every file
- [ ] Give every assignment one owner at all times
- [ ] Write one clear next action per file
- [ ] Attach an expected date or timeline to each
- [ ] Keep one file at one stage — no overlapping statuses
- [ ] Maintain a single shared tracker everyone updates
- [ ] Review the pending list at a fixed time each day
- [ ] Separate office-side delays (you control) from borrower-side delays (you chase)
- [ ] Update the status the moment a stage changes, not at week's end
- [ ] Mark submitted files as stored and retrievable

## FAQs

**Is Excel enough to track pending valuation assignments?**
For many small offices, yes — at low volume. Excel starts to strain when several people update the same file informally and the "current status" stops being reliable. The fix is not necessarily new software; it is agreeing on clear stages, one owner per file, and updating the moment something changes.

**What does "pending" actually mean in a valuation office?**
On its own, very little. It usually hides a specific stage — waiting for a site visit, documents, valuation inputs, review, or filing. Replacing "pending" with the actual stage is the single most useful change most offices can make.

**How often should the pending list be reviewed?**
Daily is ideal for offices with steady volume. At minimum, review at fixed intervals so files stuck at one stage surface before the branch calls. The review should highlight overdue files and anything waiting on the office's own action.

**Who should own a valuation assignment?**
One person at a time, depending on the stage. The owner changes as the file moves — site engineer during the visit, valuer during review, office staff during filing — but at any given moment there should be exactly one person whose move it is.

**How do we stop the branch from becoming our tracking system?**
By knowing the status of every file before the branch asks. When the office can see where each assignment is stuck and what the next step is, follow-up calls stop being surprises and start being routine updates.
